Lesson 02 / composition

One anchor, several moves

Complex animation is not a bigger animation. It is one anchor fanned out, chained in time, and handed off to a spring when a finger lets go.

16 minutes Build in chirp-mobile Prior 01 · The anchor

Lesson 01 left you with a number that persists and a function that reads it. Everything called “complex” is built from three moves on that same pair: derive many properties, chain animations in time, and let a gesture write the anchor before a spring takes over.

Fan out: one write, many properties

Keep the anchor as a single 0 → 1 progress. Let interpolate map that range onto each property. The anchor moves once per frame; every style value is arithmetic on it.

Two details matter more than they look. First, Extrapolation.CLAMP: a spring can overshoot past 1, and an unclamped opacity of 1.07 is not a value the platform likes. Second, the ranges are ordered and monotonic — interpolation is a lookup between stops, not a formula that infers intent.

This is also the answer to “should I add another anchor?”. Add one only when a value needs to move on a different schedule. If two things always move together, they are one anchor with two derived styles.

Chain: several steps, still one anchor

Animation modifiers wrap an animation function to change its shape in time. withSequence chains steps, withDelay offsets a start, withRepeat loops, withClamp limits travel. Your existing shake is the natural first conversion — same numbers, one thread better:

The legacy version needed a useEffect watching isInvalid and an Animated.sequence built on every change. Here the sequence is a value assigned when you decide the shake should happen — a press, a failed submit — and nothing runs on the JS thread afterwards.

Chain steps the same way for a two-part reveal: lead with scale, let opacity follow, or delay the second half so the eye reads them in order. Chaining is cheap because every step writes the same anchor.

Hand off: the finger writes, the spring decides

Gesture Handler callbacks are worklets, so a gesture can write an anchor directly from the UI thread. No state round-trip, no dropped frames. The pattern has exactly three parts: the finger writes during the drag, the spring settles on release, and one animated style derived from the anchor paints.

Drag it. The number in the readout is the anchor; the row is a derived style. Release before the halfway point and the spring takes it back. It is the same loop as lesson 01, with a finger in place of a button.

Three things to notice. event.translationX is relative to where the gesture began, so it needs no offset bookkeeping. onEnd derives its target from the anchor's current value — the finger's final position decides the outcome. And the spring's completion callback runs on the UI thread, so the side effect crosses back with scheduleOnRN, the current name for runOnJS.

Trap Don't call setState from onUpdate or onEnd. You will re-render the row on every frame of a drag, which is the exact cost Reanimated exists to avoid. Write the anchor; hop to JS once, at the end, if a side effect is required.

The other kind of anchor

Not every animation needs you to own the anchor. Layout animations — entering, exiting, layout — are Reanimated tracking a view's existence and position for you. You declare the behaviour; it owns the value.

The docs recommend building these outside the component or with useMemo, so a new object is not created every render. For a list, the anchor Reanimated uses is the item's identity — a stable keyExtractor is what lets it animate a reorder instead of replacing every row.

When two components share a value

A derived value is an anchor computed from another anchor. Reach for useDerivedValue when the fan-out crosses a component boundary — the row and its reply flag each need the drag progress, for example. If only styles on one view read it, compute inside useAnimatedStyle instead; one less hook is one less thing to explain later.

Spring vs timing, one line

Timing states a duration and an easing. A spring states mass, stiffness, and damping, and settles when the physics says so. Reanimated 4's defaults (damping 120, stiffness 900, mass 4) are quick and critically damped; lower the damping when you want visible bounce.

Cost check

Animate transform and opacity where you can. Width, height, and positional layout props cost a layout pass per frame — worth it for layout animations, rarely worth it by hand.

Version note

scheduleOnRN is the current name for crossing back to JavaScript. runOnJS still exists as an alias, so older snippets are not broken, only dated.
