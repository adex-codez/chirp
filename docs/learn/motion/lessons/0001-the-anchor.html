Lesson 01 / the model

The anchor

Every Reanimated animation is one value that persists and a function that reads it. Get the value right and “simple” and “complex” stop being different subjects.

12 minutes Type it in chirp-mobile Next 02 · Composition

Chirp already has one animation: the shake in code-field.tsx. It holds an Animated.Value, then a useEffect fires an Animated.sequence when the code is wrong. It works. It is also the wrong shape for almost everything else you want to build.

Reanimated asks one question before any API: what is the anchor? The anchor is the value an animation is built around — it outlives each frame, each render, and each animation that writes to it. In Reanimated the anchor is called a shared value. You create it once, change it through .value, and derive every visual from it.

That single habit explains press feedback, message arrival, and swipe gestures. They differ in who writes the anchor and how it travels, not in kind.

What happens on every frame

Three things, in order. This loop is the whole library:

  1. Something writes the anchor — a press handler, a gesture, or an animation function.
  2. Reanimated notices, on the UI thread, and re-runs the style function that reads it.
  3. The style function returns plain numbers, which are applied to the native view. React does not re-render.

The inline style={{ opacity: progress }} form works because there is nothing to compute. The moment you want opacity to stop at 0.8, or a scale to move alongside it, you need useAnimatedStyle — a function from anchors to a style, re-run on the UI thread each frame.

Trap progress = withTiming(1) rebinds a local variable and animates nothing. The anchor is mutated through its property: progress.value = withTiming(1). There is no setter and no warning.

Why the anchor lives off the JS thread

Legacy Animated with useNativeDriver: false computes frames in JavaScript. When the JS thread is busy — parsing a response, re-rendering the conversation list — frames are late, and the animation visibly hitches. A shared value is readable and writable from both threads, and Reanimated runs the style function on the UI thread as a worklet: a short function copied there and executed on the native side.

You inherit two consequences, and both are load-bearing:

  • Writes are cheap. A press handler in JavaScript can set pressed.value; the travel happens natively.
  • A worklet sees a copy. Values it closes over are captured, not live. A prop read inside an animated style is the prop from when that worklet was created. When a value must stay current, keep it in an anchor.

Which one do you reach for?

Chirp's design system already answers this for the common cases, in design.md:

Duration tokens, and the function that fits them
Token Value Reach for
state feedback — press, toggle motion.fast · 150 withTiming
element transitions — enter, exit motion.base · 250 withTiming, or a layout preset
large surfaces — sheets, screens motion.slow · 400 withTiming, often with easing
anything a finger let go of — withSpring

The rule underneath: a token names a duration, so use a function that takes a duration. Springs are for objects with momentum and mass — a released row, a knob that settles, a sheet that can be flung. A button does not have mass.

Version facts

Reanimated 4.5.1 needs RN's New Architecture and the separate react-native-worklets package. Chirp has both, and Expo wires the Babel plugin. No setup is covered here because there is nothing left to set up.

Where this lives

Vocabulary

Anchor, shared value, worklet, animated style: glossary. If a term here feels loose, that page is the fixed version.

Why not inline styles?

style={{ scale: sv }} cannot do arithmetic. useAnimatedStyle can read .value, clamp it, and fan it out. Learn the hook once.
